# K-BDS metadata mapping

Prepare a traceable review of research data against K-BDS templates. Treat the current templates and project documents as inputs, never as rules recalled from memory. Read [CA19-9 example](references/ca19-9-example.md) when working on that cohort.

For the user's pictured BioSample table, read [screenshot interpretation](references/biosample-template.md). The picture is not a complete template: obtain the current downloadable workbook before making a submission-shaped output. A project attribute sheet is distinct from BioSample, and the separate file-name guidance concerns KRA. Follow any applicable repository `AGENTS.md` instructions in the environment; do not bundle clinical data or project-specific instructions inside this skill.

1. **Establish scope and provenance.** Identify the source workbook version, sheet names, FASTQ manifest or read-only directory, current BioSample and KRA templates, and any data dictionary or researcher's decisions. Record filenames, dates, template versions or hashes. Confirm which dataset and accession relationships are actually known. Keep source files unchanged.
2. **Inventory separately.** List every clinical column with its sheet, header, value type, representative non-identifying values, blank/sentinel counts, and apparent meaning. Count cohort rows, unique clinical sample IDs, FASTQ files and R1/R2 pairs independently. Detect duplicate IDs, unpaired reads, alternate file versions and QC failures. Never equate a patient, biological sample, library, experiment and read run merely because labels look alike.
3. **Classify source fields.** Group columns into identifiers/QC, patient characteristics, specimen/tumor, clinical stage and pathology, imaging/biomarkers, surgery/treatment, and outcomes. Mark whether each field belongs in a submission template, supplementary clinical metadata, an internal linkage table, or needs expert review. A clinically important field need not have a matching K-BDS template field.
4. **Compare each template field.** Read the exact current BioSample/KRA column names, requiredness, definitions, accepted values and sheet instructions from the supplied templates or current official guidance. For each target field record source column, transformation, unit, row granularity, evidence pointer, confidence, and state: `DIRECT`, `DERIVED`, `MISSING`, `AMBIGUOUS`, or `NOT_APPLICABLE`. Do not guess organism, tissue, collection date, library strategy, layout, platform, instrument, project/study ID, or consent/IRB terms. Distinguish a truly required field from one merely present in an example workbook.
5. **Reconcile records.** Join clinical IDs to FASTQ stems using an explicit documented rule, preserving both identifiers. Verify pair counts and QC status. Keep QC-failed clinical cases in the clinical inventory while recording why no sequencing file maps to them. Flag many-to-one or one-to-many links for review. Avoid filling a BioSample or KRA row until its biological relationship and intended submission unit are confirmed.
6. **Produce review artifacts.** Make (a) a source-column classification table, (b) a BioSample field mapping table, (c) a KRA field mapping table, (d) a sample/read reconciliation table, and (e) an unresolved-questions list. Include counts, source provenance, and explicit `UNCONFIRMED` values. A draft spreadsheet may copy target headers, but label it `검토용 초안 — 제출 불가` until template validation, researcher confirmation and portal checks are complete. Do not put patient-identifying information in a report or public artifact.
   For the pictured BioSample form, use `scripts/fill_biosample.py` with `--source CLINICAL.xlsx --template EMPTY_BIOSAMPLE.xlsx --config FACTS.json --output DRAFT.xlsx --audit REVIEW.csv`. Minimal `FACTS.json`: `{ "first_data_row": 4, "approved_facts": {} }`; add `"age_unit": "years"` only after confirmation. A confirmed field uses `"approved_facts": {"Organism": {"value": "Homo sapiens", "evidence": "researcher confirmation, date and document"}}`. The script preserves the supplied workbook structure, writes QC-passing sample names and supported fields, and audits every source row. Inspect template validation and every output cell afterward. If the downloaded template has protected cells, formulas, merged data regions, or a different header arrangement, adapt or fill it manually while preserving its instructions; never use the screenshot as a fabricated official workbook.
7. **Check results.** Verify all source columns accounted for, unique sample counts and R1/R2 pairing, missing required fields, units and controlled values. Report conflicting evidence and assumptions rather than silently resolving them. Explain that file organization or checksum verification does not establish metadata readiness. Do not upload or submit to K-BDS without a separate explicit request and the requisite review.

Use the user's established file-organizing skill only for its own inventory/plan/apply/verify scope; this skill covers field-level metadata comparison and must not inherit `submission_ready` from copied-file verification.
